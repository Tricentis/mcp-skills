# DI workflow — business rules to SQL

Turn natural-language or pseudo-code business rules into a Data Integrity row-by-row comparison. SQL is generated by the LLM from schema + rules — there is no `generate_sql` MCP tool.

Load **di-orchestration.md**, then this file. Schema steps are the canonical recipe in [conventions.md](../conventions.md).

Follow this graph. Do not add steps that are not on it.

```text
ingest rules → List
  usable connection exists? ──yes (default)──► Get → allowAiQueries?
       │                              no → stop (enable Allow AI queries in UI)
       │                              yes → infer DBMS (or ask) → runSql catalog
       │                                    → LLM SQL → confirm
       │                                    → createRowByRowComparison (or teststep_edit SQL-only)
       │                                    → tosca_testcase Get
       │                                    → user asked to run? no → stop
       │                                                      yes → tosca_testrun_edit Create → tosca_testrun Get
       └──no or user asked create/test──► optional diconnection_edit → UI secrets
                                           → optional testConnection → back to List
```

**Default:** existing connection → schema → SQL → `createRowByRowComparison` → `tosca_testcase` Get → **stop**.

**Optional (not Story 2 AC):** create/update/test connection; `tosca_testrun_edit` Create only if the user asks to run.

```text
Business rules → SQL:
- [ ] Ingest rules (NL or pseudo-code)
- [ ] tosca_diconnection List
- [ ] Optional create/test only if List empty or user asked — then back to List
- [ ] Get → allowAiQueries → infer DBMS → runSql catalog (per connection SQL will hit)
- [ ] LLM dialect SQL from rules + schema; confirm SQL, RowKey, remaps
- [ ] createRowByRowComparison (default) or teststep_edit SQL-only patch
- [ ] tosca_testcase Get
- [ ] Stop unless the user asked to run → tosca_testrun_edit Create → tosca_testrun Get
```

## 1 — Ingest rules

Capture source of truth (expected), target of truth (actual), filters, joins, and which columns must match. Do not write SQL yet.

Jira: ingest pseudo-code (e.g. `IF order.status = 'SHIPPED' AND order.date >= TODAY-30 THEN include`) or natural language.

## 2 — List, then fork

```
Call tosca_diconnection List
```

Pick **source** (expected / business-rule side) and **target** (actual) from the list. Same connection twice is allowed.

| Fork | Do |
|------|----|
| Usable source and target exist **and** user did not ask to create/test | Get (next section). This is the default. |
| List empty, **or** user asked to create / update / test | `reference/workflows/di-connection.md` — only the operation they asked for. Secrets in Connection Manager. Then **back to List**. Do not invent SQL. |

## 3 — Schema (canonical five steps)

For **each** connection the SQL will hit:

1. `tosca_diconnection` Get
2. If `allowAiQueries` is false → **stop**; enable Allow AI queries in Connection Manager (MCP cannot set it)
3. Infer DBMS from `dataSourceType`, name, description, `metadata.databaseCategory`
4. If unclear → ask
5. Catalog `SELECT` via `tosca_dataintegrity_runSql` → open `launcherLink` → poll `checkSqlResult`

Use inner Ulid `id.id` for Get/`runSql`. Comparison create uses `connectionName`.

## 4 — Generate SQL (LLM)

Write dialect-correct, read-only `SELECT`s that implement the rules against the catalog.

- **Source `sqlStatement`** = expected result (the business-rule query). This is the Jira inject target.
- **Target `sqlStatement`** = actual data to compare (often the same tables without the rule, or a second rule). Ask if only one side is specified.
- Prefer explicit columns. RowKey names must match **after remaps**.

## 5 — Confirm

```
Source connection: <name>   (expected / rules)
Source SQL: SELECT ...
Target connection: <name>   (actual)
Target SQL: SELECT ...
RowKey: <column(s)>
Remaps: <from → to, or none>
```

## 6 — Write

| Situation | Tool |
|-----------|------|
| New test case, remaps, tolerances, cell settings, or new endpoints | **`tosca_dataintegrity_createRowByRowComparison`** — fill `source.sqlStatement` (rules), `target.sqlStatement`, `connectionName`s, `rowKey`, `sourceOptions.columnRenames` / `targetOptions.columnRenames` (`from`/`to`) when names differ |
| User pointed at an **existing** Complete Row by Row Comparison step and only SQL text (maybe connection name) changes — no remaps/tolerances | `tosca_teststep_edit` on `Source.Database.ODBC.SQL Statement` / `Target.Database.ODBC.SQL Statement` |

Do **not** use `explicitName` on `teststep_edit` for column remaps.

## 7 — Verify

`tosca_testcase` Get. Default: **stop**.

## 8 — Optional run (not Story 2 AC)

Only if the user asked to run this test case: `tosca_testrun_edit` Create → open `agentLink` if needed → Create again → `tosca_testrun` Get until terminal (`reference/workflows/trial-run-testcase.md`).

Playlist / unattended run only if they explicitly want a batch run — not the default execute path.

Do **not** start a run unprompted. Do not analyze results in conversation.
